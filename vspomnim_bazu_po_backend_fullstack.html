Тема 01 · Основы веба

Клиент, сервер и связь между ними

Почти всё в вебе и бэкенде построено вокруг одной простой идеи: кто-то просит, кто-то отвечает.

Клиент

Программа, которая запрашивает данные и показывает их пользователю. Это твой браузер, мобильное приложение или даже другая программа, которая обращается за информацией.

Сервер

Программа (обычно постоянно работающая на удалённом компьютере), которая хранит данные и логику и отвечает на запросы клиентов. Backend-разработчик пишет именно код сервера.

Когда ты открываешь сайт, твой браузер (клиент) отправляет запрос на сервер. Сервер собирает нужные данные — например, достаёт их из базы данных — и отправляет обратно готовую страницу или JSON с данными, которые ты видишь на экране.

Тема 02 · Как всё это находит друг друга

HTTP, HTTPS, DNS и IP

Четыре термина, которые постоянно путают на старте. Разберём каждый простыми словами.

IP-адрес

Уникальный «адрес» устройства в сети — набор цифр вроде 192.168.1.1. Без него компьютеры просто не смогли бы найти друг друга.

DNS

«Телефонная книга интернета». Превращает понятное имя google.com в его настоящий IP-адрес — людям проще запомнить имя, чем набор цифр.

HTTP

Протокол — общий «язык», по которому браузер и сервер разговаривают друг с другом: как оформить запрос и как оформить ответ.

HTTPS

Тот же HTTP, но с шифрованием (S = Secure). Данные по пути от клиента к серверу нельзя подсмотреть или подделать — именно поэтому у современных сайтов в адресной строке всегда https, а не http.

Основные HTTP-методы

МетодЧто делает
GETПолучить данные — например, список пользователей
POSTСоздать что-то новое — например, зарегистрировать пользователя
PUT / PATCHИзменить существующие данные
DELETEУдалить данные
Пример из практики

Когда ты вводишь в браузере google.com — происходит цепочка: DNS превращает имя в IP-адрес → браузер по HTTPS отправляет GET-запрос на этот IP → сервер обрабатывает запрос и отправляет обратно готовую страницу.

Тема 03 · Как программы общаются друг с другом

API простым языком

API (Application Programming Interface) — интерфейс, через который одна программа может обращаться к другой, не зная, как та устроена внутри.

Аналогия с рестораном

Ты не идёшь на кухню готовить блюдо сам — ты даёшь заказ официанту. Официант (API) передаёт заказ на кухню (сервер), а потом приносит тебе готовое блюдо (ответ). Тебе не нужно знать, как устроена кухня — важно только то, что можно заказать и что ты получишь.

REST API на примере

REST — самый популярный стиль построения API: у каждого действия есть свой адрес (endpoint) и свой HTTP-метод.

ЗапросЧто происходит
GET /usersПолучить список всех пользователей
GET /users/5Получить пользователя с id = 5
POST /usersСоздать нового пользователя
DELETE /users/5Удалить пользователя с id = 5
Пример из практики

Когда приложение погоды показывает тебе прогноз — оно не «знает» погоду само. Оно отправляет запрос к API метеослужбы, получает данные в ответ и красиво их показывает. Это и есть работа с чужим API.

Тема 04 · Где хранятся данные

Базы данных: какие бывают

База данных — организованное хранилище, откуда можно быстро находить, добавлять и изменять информацию. Есть два больших типа.

Реляционные (SQL)

Данные хранятся в таблицах со строгой структурой — строки и столбцы, таблицы связаны между собой. Подходят, когда важна строгая структура и связи между данными (заказы, пользователи, платежи).

Примеры: PostgreSQL, MySQL, SQLite

Нереляционные (NoSQL)

Более гибкая структура хранения — без строгих таблиц. Подходят для быстро меняющихся данных, кэша, больших объёмов, где строгая структура не нужна.

Примеры: MongoDB (документы), Redis (ключ-значение)

База данныхТипОбычно используют для
PostgreSQLSQLОсновное хранилище данных приложения
MySQLSQLТо же самое, чуть проще в настройке
MongoDBNoSQLГибкие данные без строгой структуры
RedisNoSQLОчень быстрый кэш и временные данные
Пример из практики

Интернет-магазин обычно хранит заказы и пользователей в PostgreSQL (данные строго структурированы и связаны), а корзину покупок или сессию пользователя — в Redis (нужна максимальная скорость, а данные временные).

Тема 05 · Язык общения с базой данных

SQL: что это и зачем

SQL (Structured Query Language) — язык для общения с реляционной базой данных: получать, добавлять, изменять и удалять данные. Практически весь backend так или иначе работает с базой через SQL — даже если инструменты вроде ORM это прячут.

Представим таблицу users

idnameagecity
1Анна25Москва
2Игорь17Казань
3Мария31Москва

Базовые запросы

-- получить всех пользователей
SELECT * FROM users;
-- получить только тех, кто старше 18
SELECT name, age FROM users WHERE age > 18;
-- вернёт: Анна (25), Мария (31)
-- добавить нового пользователя
INSERT INTO users (name, age, city) VALUES ('Олег', 22, 'Сочи');
-- изменить возраст Анны
UPDATE users SET age = 26 WHERE name = 'Анна';
-- удалить пользователя
DELETE FROM users WHERE name = 'Игорь';
Пример из практики

Когда ты фильтруешь пользователей на сайте по городу «Москва» — за кулисами почти всегда стоит примерно такой запрос: SELECT * FROM users WHERE city = 'Москва'. SQL — это то, на чём держится почти любая выборка данных в приложении.

Тема 06 · Как приложение доезжает до сервера без сюрпризов

Docker простым языком

Docker — способ упаковать приложение вместе со всем, что ему нужно для работы (библиотеки, версии, настройки), в один «контейнер», который одинаково запустится на любом компьютере.

Аналогия с грузовым контейнером

Неважно, что внутри контейнера — мебель или техника: он одного стандартного размера и одинаково едет на любом корабле или поезде. Docker-контейнер с приложением так же одинаково «едет» и запускается на любом сервере — с той же версией Python, тех же библиотек, тех же настроек, что и у тебя на компьютере.

Пример из практики

Классическая проблема — «у меня на компьютере работает, а на сервере нет» — обычно возникает из-за разных версий Python, библиотек или настроек окружения. Docker решает это раз и навсегда: всё нужное окружение упаковано внутрь контейнера и переезжает вместе с приложением.

Тема 07 · На чём это всё пишут

Основные языки и технологии

Не нужно знать всё сразу — но полезно понимать, как называются основные инструменты и для чего они нужны.

Backend

Python + FastAPI/Django

Самый популярный старт — простой синтаксис, много готовых инструментов

Go

Высокая производительность, любят за инфраструктуру и нагруженные сервисы

Java + Spring

Стандарт крупного enterprise и банковского сектора

Node.js + TypeScript

JavaScript и на бэкенде — удобно, если фронтенд уже на JS

Frontend (для фуллстека)

HTML и CSS

Структура и оформление страницы — фундамент любого интерфейса

JavaScript / TypeScript

Логика на странице — то, что делает сайт интерактивным

React

Самая популярная библиотека для интерфейсов — компоненты и состояние

REST API

Способ, которым фронтенд и бэкенд обмениваются данными

Пример из практики

Типичный фуллстек-стек выглядит так: React на фронтенде рисует интерфейс → он делает запросы к API, написанному на Python/FastAPI → бэкенд достаёт данные из PostgreSQL → всё это упаковано в Docker-контейнеры, чтобы одинаково работать и локально, и на сервере.
